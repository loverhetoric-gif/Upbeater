# Upbeater あらゆる局面への対応

この文書の全項目は**実装の受け入れ条件**である。各項目に対応する自動テスト（故障を意図的に起こすテスト）を用意し、すべて通るまで完成としない。

## 大原則

1. **端末を壊さない**：どの段階で失敗しても、端末には必ず「動く版」が残る
2. **取りこぼさない**：通知が届かなくても、いずれ最新版に追いつく
3. **止まらない**：失敗は段階・理由・再試行の可否として記録し、自動で再試行する。人の判断が要るものだけを通知する
4. **何度実行しても同じ結果**：すべての操作を冪等にし、途中から再開できるようにする
5. **Hub は実行の前提ではない**：Hub が停止しても、各端末のアプリは現行版で動き続ける

## GitHub と Hub

| 局面 | 対応 |
| --- | --- |
| Webhook の重複・順序の入れ替わり | 配信 ID で重複を捨てる。到着順ではなく、受信のたびに GitHub API で main の現在のコミットを照会して判断する |
| Webhook の取りこぼし | 定期的に全アプリの main を照合する（保険としての巡回） |
| 強制プッシュ・履歴の巻き戻し | 版はコミット SHA と Hub が発行する通番で管理する。main が過去の状態に戻った場合も、新しい通番の版として配信する |
| 短時間に連続した更新 | 最新のコミットだけを扱う。進行中の古いビルド・配信は取り消す |
| GitHub の障害・回数制限 | 待ち行列に保持し、間隔を広げながら再試行する |
| GitHub App の権限失効・秘密鍵の期限 | 検知して利用者へ通知。期限の前に予告する |
| Hub 自体の障害 | 端末は現行版で動作を続け、復旧後に照合して追いつく |
| 署名用の秘密鍵の漏えい・更新 | 鍵に世代番号を付ける。端末は複数の公開鍵を受け入れ、失効した世代を拒否できる |

## ビルド（Builder）

| 局面 | 対応 |
| --- | --- |
| Mac が停止・スリープ中 | 指示は Hub の待ち行列に残す。復帰時に各アプリの最新版だけをビルドする |
| ビルド失敗 | 配信しない。現行版を維持し、失敗の記録（末尾ログを含む）を残す。MCP から取得できる |
| 途中で中断 | 作業場所を破棄して最初からやり直す。中途半端な成果物は絶対に上げない |
| 複数アプリの同時更新 | 順番に処理する。同じアプリの古い指示は統合する |
| ビルドに必要な道具の不足 | 開始前に点検し、不足を具体的に報告する |
| 署名の資格情報 | Android の署名鍵・Apple の証明書を失うと更新できなくなるため、保管場所を二重化し、期限の前に予告する |

## 配信と通信

| 局面 | 対応 |
| --- | --- |
| 通知が届かない（FCM・APNs は到達保証なし） | 起動時・復帰時・定期的に端末から Hub へ照合する（プッシュが主、照合が保険） |
| 端末が長期間オフライン | 復帰時に途中の版を飛ばして最新版へ直接更新する |
| ダウンロードの中断 | 続きから再開する。完了し検証を通ったものだけを適用する |
| 署名・SHA-256 の不一致 | 破棄して再取得。繰り返す場合はその版を配信停止にして通知する |
| 古い版へのすり替え（攻撃） | 通番が現行版より小さい版は、署名付きの明示的な巻き戻し指示がない限り拒否する |
| 空き容量の不足 | 事前に確認し、不足なら保留して報告する |
| 従量制通信・低電力モード | 端末ごとの設定に従い、Wi-Fi 接続時まで待つことができる |

## インストール

| 局面 | 対応 |
| --- | --- |
| インストールの失敗 | 直前の版へ自動で戻す。端末には直近 2 つの版を保持する |
| 入れ替え後に起動しない | 新しい版の起動成功を確認する。一定時間内に確認できなければ自動で戻し、その版を配信停止にする |
| 対象アプリが使用中 | アプリごとの設定に従う（終了を待つ／次回起動時に適用／即時に再起動） |
| 利用者データ | 入れ替えでデータを消さない。Android は同じ署名鍵、iOS は同じバンドル ID とチームを必ず維持する |
| 権限の喪失（Android の導入許可の取り消し、iOS の署名期限切れ） | 検知して一度だけ案内する。署名期限は切れる前に自動で更新し、できなければ予告する |
| Upbeater 自身の更新失敗 | 自己更新は別プロセスを介して行い、失敗時は前の版で起動する。更新の仕組み自体が動かなくなる状態を作らない |

## 配信の安全装置

- **段階配信**：アプリごとに「先行する 1 台で成功 → 残り全台」を選べる
- **一時停止**：全体・アプリ単位・端末単位で配信を止められる（MCP からも操作可能）
- **失敗の連鎖を止める**：同じ版が複数台で失敗したら、自動で配信を止める

## GitHub 操作（MCP 経由）

| 局面 | 対応 |
| --- | --- |
| 途中の段階で失敗 | 各段階を冪等にし、履歴から失敗した段階以降を再開する |
| マージ時の衝突 | main を取り込んで再試行。解消できなければ PR を残し、衝突箇所を具体的に返す |
| ブランチ保護・必須の検査 | 満たせない条件を具体的に返す |
| 同じ依頼の重複実行 | 依頼 ID で重複を検知し、既存の結果を返す |

## 見える化

- すべての操作を `operations` に段階ごとに記録し、MCP と管理画面から参照できる
- 端末ごとに「いま動いている版・最後に照合した時刻・未適用の版」を常に把握する
- 人の判断が必要な失敗だけを利用者へ通知する（自動で回復したものは記録のみ）
