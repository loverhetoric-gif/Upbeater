# Upbeater 自動処理（Actions 代替）のあらゆる局面への対応

`docs/RESILIENCE.md` と同じく、全項目が**実装の受け入れ条件**である。各項目に故障を意図的に起こすテストを用意する。

| 局面 | 対応 |
| --- | --- |
| Runner が停止中 | ジョブは待ち行列に保持する。`linux` はクラウド Runner へ回す。`macos` 専用は復帰を待ち、一定時間を超えたら通知する |
| 実行中に Runner が落ちる | 心拍が途絶えたら失敗として扱い、再実行する。再実行してはならない手順はジョブ単位で指定できる |
| 時間超過 | 打ち切り、子プロセスまで確実に終了させる |
| 新しい更新が来た | 同じ `concurrency` の古いジョブを取り消す。公開系は直列化して同時実行させない |
| ログ送信の途切れ | Runner 側に保持して再送し、通番で並べ直す |
| 秘密情報の露出 | ログ上で自動的に伏せる（base64 などの変形も含む） |
| 作業場所の汚染 | 毎回使い捨ての作業場所で実行する |
| 定義ファイルの誤り | 実行前に検証し、ファイル名と行番号を付けて報告する。GitHub にも失敗として表示する |
| GitHub への結果表示の失敗 | 再試行する。表示できなくても実行自体は止めない |
| フォークからの PR | 秘密情報を渡さない |
| 無限の連鎖 | Upbeater 自身が作ったコミットを合図にするかどうかを設定で制御し、既定では合図にしない |
| 定期実行の取りこぼし | Cron の実行履歴を照合し、抜けた回を一度だけ実行する |
| Hub の停止中の Webhook | GitHub 側の再送と、定期照合の両方で回復する |
| 同じジョブの二重実行 | ジョブ ID で排他し、二つ目は実行しない |
